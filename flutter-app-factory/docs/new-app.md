# New app creation guide

Work from the factory root. Each step is local and free except where noted.

## 1. Create

```bash
python3 automation/scripts/factory.py create --name "Battery Analyzer" --slug battery_analyzer --org com.example
```

- `--org` must be a reverse-domain identifier. `com.example` is a development
  placeholder, never publishable; release validation rejects it.
- The command runs `flutter create`, overlays `templates/flutter_app`,
  writes `app.yaml`, syncs native flavors, registers the app, regenerates
  `codemagic.yaml`, and runs `flutter pub get` + format. Requires Flutter.
- Idempotent: same name + derived identity returns `already_exists` and
  changes nothing. A colliding identifier with another app is rejected.

## 2. Inspect

```bash
cat apps/battery_analyzer/app.yaml
python3 automation/scripts/factory.py list
```

Confirm the slug, Android/iOS IDs, `lib/main_dev.dart`, `lib/main_prod.dart`,
`config/dev.json`, `config/prod.json`, and `store/en-US.yaml`.

## 3. Flavors

Dev/prod flavors are generated by `create`. To change endpoints or IDs later,
edit `apps/<slug>/app.yaml`, then:

```bash
python3 automation/scripts/factory.py flavors battery_analyzer
python3 automation/scripts/factory.py validate battery_analyzer
```

Keep `dev` IDs suffixed (`.dev`) and prod IDs clean; never put prod URLs or
keys in the dev flavor or vice versa.

## 4. Optional services

```bash
python3 automation/scripts/factory.py configure battery_analyzer --admob
python3 automation/scripts/factory.py configure battery_analyzer --firebase
```

These write local configuration only. They do not create AdMob accounts, ad
units, or Firebase projects — those need the owner in the respective console
(see `docs/credentials.md`). Firebase stays optional; AdMob uses test IDs in
dev and blocks release until real prod unit IDs are supplied.

## 5. Validate, test, build plan

```bash
python3 automation/scripts/factory.py validate battery_analyzer
python3 automation/scripts/factory.py test battery_analyzer
python3 automation/scripts/factory.py build battery_analyzer --flavor prod --platform android
```

`test` runs format check, `flutter analyze`, and `flutter test` for the app
and all shared packages. `build` without `--execute` prints the exact Flutter
command without touching native projects or tools; `--execute` runs a local
build (free, needs Android SDK/Xcode for device targets).

## 6. Store metadata and assets

```bash
python3 automation/scripts/factory.py metadata battery_analyzer
python3 automation/scripts/factory.py assets battery_analyzer
```

`metadata` validates `store/en-US.yaml` against Play/App Store limits and
exports provider-format JSON. `assets` writes launcher-icon/splash configs;
with `--execute` and real source art it generates native variants. Neither
command creates artwork or proves visual approval.

## 7. Codemagic

```bash
python3 automation/scripts/factory.py ci-generate
```

Then follow `docs/codemagic.md` for the one-time connection, environment
groups, and signing setup. Triggering any remote build needs explicit
authorization — it spends paid CI minutes.

Next: `docs/release.md` for the testing-to-production path.
