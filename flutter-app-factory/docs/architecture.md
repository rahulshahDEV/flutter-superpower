# Architecture

## Monorepo

```
flutter-app-factory/
  apps/<slug>/          app.yaml, config/dev.json, config/prod.json,
                        store/en-US.yaml, android/, ios/, lib/, test/
  packages/             core, ui_kit, analytics, ads, networking, app_config
  templates/            flutter_app/ starter, app_config/app.yaml schema,
                        store_metadata/en-US.yaml, feature/ skeleton
  automation/
    scripts/factory.py  CLI: list init create flavors configure validate test
                        build assets metadata ci-prepare ci-trigger release
                        status ci-generate
    scripts/            operations.py (local mutations), orchestrator.py
                        (release plans/journal), integrations.py, native.py
                        (Android/iOS flavor sync), model.py (schema/paths)
    workflows/ci.py     codemagic.yaml generator (6 explicit workflows/app)
    validators/release.py  release-readiness checks (blocks on critical)
    publishing/         play.py, apple.py, apple_metadata.py, artifacts.py,
                        google_auth.py, apple_auth.py, common.py
    tests/ validators   offline unit tests (unittest, no network)
  .agents/skills/       12 canonical skills, shared by OpenCode and Codex
  .opencode/commands/   11 slash commands loading the skills
```

## App identity (`app.yaml`)

Schema version 1. Sections: `app` (name, slug, version, build_number),
`android` / `ios` (base IDs, signing references, team), `flavors.dev|prod`
(per-flavor IDs, `api_url`, `firebase_project`), `feature_flags`,
`monetization` (AdMob app IDs + per-platform ad units; empty = unconfigured),
`firebase` (enabled + services), `platforms`, `deployment` (Codemagic IDs,
environment groups, credentials variable), `privacy` (policy URL, permissions,
review flags), `assets` (icon/splash paths, reviewed flag).

`templates/app_config/app.yaml` is the schema reference; `create` substitutes
`__APP_TITLE__`, `__APP_NAME__`, `__ORG__`, `__APP_ID__`.

## Flavors

`dev` and `prod` are separate Android `productFlavors` dimensions and iOS
schemes/build configurations, generated by `native.py` from `app.yaml`.
Entry points: `lib/main_dev.dart` / `lib/main_prod.dart`, runtime config in
`config/dev.json` / `config/prod.json` (public values only). Dev builds are
debug APKs / simulator apps; prod Android is a signed release AAB, prod iOS a
signed IPA. Release validation rejects placeholder orgs, prod IDs ending in
`.dev`, and dev credentials in prod config.

## Shared packages

Apps depend on the six `packages/` via path dependencies. They carry the house
architecture (SafeCubit, Either failures, DI, theme tokens, AdMob adapter,
analytics facade, Dio client, flavor config). Bugs fixed there propagate to
all apps; changes require `flutter analyze` + `flutter test` in every affected
package.

## CI generation

`workflows/ci.py` emits six explicit workflows per app (dev/prod ×
android/ios builds plus `prod-android-internal` and `prod-ios-testflight`
distribution workflows). Codemagic does not support dynamic workflow selection,
so generation — not templating — is the mechanism. Each workflow is scoped by
`when.changeset` to its app plus `packages/` and `automation/`, so unrelated
apps never rebuild. Regenerate after every `create`, flavor, or deployment
change: `factory.py ci-generate`.

## Release flow

`release` without flags writes a plan plus a resumable journal under
`.factory/` (gitignored). With `--execute --authorize-testing` (the user's
attested authorization, not a substitute for it) it triggers the matching
Codemagic workflows via `ci-trigger` and records build IDs. `status --provider
release` resumes the journal; `status --provider codemagic` reads one build.
The journal tracks CI; store deployment is confirmed separately through the
`publishing/` adapters against official APIs. See `docs/release.md`.
