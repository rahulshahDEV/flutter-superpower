# AGENTS.md — working in the Flutter App Factory

This file governs every agent working in this monorepo. The skill system in
`.agents/skills/` and the commands in `.opencode/commands/` implement these
rules; read the relevant `SKILL.md` before acting.

## Source of truth

- `apps/<slug>/app.yaml` plus the `factory.yaml` registry define app identity.
  Read them before modifying anything. Never guess identifiers.
- `codemagic.yaml` is generated by `ci-generate`. Never hand-edit it.
- `templates/` is the starter. Fix the template rather than patching every app.

## Behavior

1. Inspect the working tree, existing configuration, and closest implementation
   before editing. Reuse; make minimal changes; never silently overwrite
   important configuration — show the diff.
2. `create` is idempotent. An existing app means inspect or resume it, never
   regenerate it blindly.
3. Unknown production values stay explicit placeholders (`REPLACE_ME`, empty
   strings). They block release; never substitute dev values to make validation
   pass, and never let dev credentials leak into prod flavors.
4. Validate everything you touch: `validate`, then `test` for the affected app.
   Report exact commands, results, failures, and what you did not verify.
5. Never fabricate build, upload, or deployment success. Distinguish local
   validation, build completion, artifact upload, store processing, testing
   availability, review, and public availability.
6. Ask only when essential information is missing (real org domain, account
   facts, artwork). Propose the default and proceed with placeholders otherwise.

## Hard prohibitions

- No secrets in code, logs, or reports. No passwords, API private keys, service
  account JSON, keystores, or signing passwords in the repo.
- No `--execute`, `--authorize-testing`, CI triggers, uploads, or publishing
  without the user's explicit authorization for that concrete action.
- No production publishing path by default. Prepare a reviewable action and
  require fresh approval bound to app/version/build/artifact/destination.
- No Playwright for anything an official API covers; never CAPTCHA, store
  review, or account-security bypasses.
- Never commit generated files (`.g.dart`, `.freezed.dart`,
  `injection.config.dart`), build outputs, or local env files.

## Quality gate (Flutter changes)

```bash
dart format .
flutter analyze      # 0 issues
flutter test         # all green
```

Prefer `fdev gen` for codegen when installed, else
`dart run build_runner build --delete-conflicting-outputs`.
