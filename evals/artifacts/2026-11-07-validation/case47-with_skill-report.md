# Implemented

Kept the existing sqlite3 framework and Draft/DraftDatabase public API. The opener now applies schema 1 → 2 → 3 steps in a single BEGIN IMMEDIATE transaction, including user_version and failure hooks. Fresh files reach schema 3. Failures roll back all upgrade steps, close the connection, and propagate to the caller without deleting files. Future versions are rejected. Draft reads/writes now persist timestamps and JSON-encoded tags.

The v3 schema is additive: updated_at defaults to 0, tags_json defaults to '[]', and drafts_updated_at indexes updated_at. Previous v2 explicit-column reads, inserts, and updates remain usable; rollback means using old SQL against schema 3, with no schema downgrade.

# Notes

The opener serializes migration with SQLite's writer lock. A concurrent writer can receive SQLite's normal busy error; this change does not introduce retry policy. Invalid stored JSON remains an explicit read error rather than being silently replaced. The implementation never deletes corrupt or unsupported databases.
